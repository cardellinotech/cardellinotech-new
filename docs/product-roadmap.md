## Build Philosophy

1. **Each phase ships something demoable.** After Phase 0, the app runs. After Phase 1, the upper half of the page is live. After Phase 2, the full page works including the contact form.
2. **Infrastructure before content.** The first phase sets up the entire technical foundation so every subsequent task is just writing components and content.
3. **Magic moment first.** Case studies are built in Phase 2, early in the content phase — the CTO reading their problem in a case study is the primary conversion trigger.
4. **Test as you go.** After each task, run the dev server and verify the output. Don't save testing for the end.
5. **Progressive enhancement.** Core content and function first, visual polish in Phase 3.
6. **Review before proceeding.** Push each completed phase as a PR. Let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase.
7. **Visual tokens first.** Before implementing any component styling, run `/plaid design` with image references to generate `docs/design.md`. This roadmap assumes `docs/design.md` exists by the time Phase 1 begins. If it doesn't, create it during Phase 0 (see TASK-004).

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections. Read only those sections, not entire documents.
3. **Let it work:** The agent reads the roadmap, finds the first unchecked task, implements it, and marks it complete in `docs/product-roadmap.md`.
4. **One session = one phase:** Try to complete a full phase in one session for best continuity. If you stop, resume from the first unchecked task.
5. **Push a PR for review:** After each phase, push a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase.
6. **Update the status line:** After completing tasks, update the header: `**Status:** X/34 tasks complete`.

### Session Tips

- **Don't skip tasks.** Tasks are ordered intentionally — skipping creates dependency issues.
- **Verify after each task.** The task's Notes section ends with a verification step. Run it before marking complete.
- **Phase 0 is the longest setup.** After Phase 0, subsequent phases are mostly component work — faster to execute.
- **Case studies are the most important content.** Don't leave these as placeholders. Write them specifically and technically.
- **Review before moving on.** Each phase PR should be reviewed before the next phase starts.
